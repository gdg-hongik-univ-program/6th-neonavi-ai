# 경로 수집 설계 — 카카오 어댑터 & Pool 확대

> 확정: 2026-07-13 · 담당: 안중현(AI) · 실측 검증 기반. 구현 변경 시 이 문서도 갱신.
> 관련: [Phase0_계약.md](./Phase0_계약.md)(특성 10개·pairwise), [AI_구현계획.md](./AI_구현계획.md)

## 목적
학습용 실경로 데이터를 모으기 위해, 한 출발지-목적지(O-D)에서 **서로 다른 경로를 최대한 많이** 확보한다. 카카오 길찾기 REST API는 한 번 호출에 보통 1개만 주므로, 다중 호출 + 경유지 교란으로 pool을 넓힌다.

## 카카오 API 기본
- 엔드포인트: `GET https://apis-navi.kakaomobility.com/v1/directions`
- 인증: 헤더 `Authorization: KakaoAK ${KAKAO_REST_API_KEY}` (`.env`, gitignore)
- 좌표: `"경도,위도"` (x=lng, y=lat)
- 키 검증됨(2026-07-13): `result_code:0` 정상 응답, 아래 필드 실존 확인.

## Pool 확대 전략 (실측 검증)

### 두 레버
1. **priority 다중** — `RECOMMEND`, `DISTANCE` 사용. (TIME·MAIN_ROAD·NO_TRAFFIC_INFO는 RECOMMEND로 수렴 → 무의미)
2. **경유지 수직 교란** ⭐ — O-D 직선의 **수직 단위벡터** 방향으로, 경로상 1/3·1/2·2/3 지점을 offset(±0.008/0.016/0.024도)한 점을 `waypoints`로 강제 → 다른 회랑 생성. **이게 실질 레버.**

### 중복 제거
- 각 경로를 지나는 좌표를 **~100m 격자(round 3자리) 집합**으로 변환 → **Jaccard > 0.8 이면 같은 길**로 보고 하나만 유지.

### 실측 결과 (강남역→판교역)
- priority 5종 → distinct **2개** (priority만으론 약함)
- priority 2종 + 경유지 교란 17호출 → **distinct 12개**
- 확보 스펙트럼: 통행료 0~2000원, 거리 15~35km, 시간 19~45분 → 성향 차별·학습에 충분한 다양성.

### 우회 허용(detour cap)으로 pool 크기 조절
| best 시간 대비 | 경로 수 | 용도 |
|---|---|---|
| ≤1.5x | ~3 | 서빙/데모 (말 되는 대안만) |
| 제한 없음 | ~12 | **학습 수집 (다양성 최대)** |

## 어댑터 인터페이스 (예정: `ai/adapters/kakao.py`)
```
fetch_pool(origin, dest, mode='collect') -> list[CandidateRoute]
  mode='collect' : 우회 제한 없음, dedupe 후 전부      ← 현재 단계에서 사용
  mode='serve'   : best시간 ×1.5 이내 top~5           ← 서빙 단계(나중)
```
- **현재 방침: `collect` 모드로 최대 수집.** serve 모드는 서빙 단계에서 구현.
- O-D당 호출 수 = pool 크기. 다양성은 **여러 O-D**에서도 오므로, 수집 효율상 **O-D당 6~8호출**로 잡고 O-D 개수를 늘린다.

## 응답 → CandidateRoute 매핑
| CandidateRoute | 카카오 응답 | 비고 |
|---|---|---|
| coords `[(lng,lat)]` | `sections[].roads[].vertexes` 2개씩 | 곡률 계산과 좌표계 일치 |
| distance_km | `summary.distance`/1000 | |
| duration_min | `summary.duration`/60 | |
| toll | `summary.fare.toll` | 실존 확인 |
| congestion(원천) | `roads[].traffic_state` (거리가중) | **4=원활,1=정체 → 부호 반전 필요** |
| turn_count(원천) | `guides[]` 개수 | 실존 확인(17~18개). type 코드 의미표는 역매핑 필요 |
| guides | `sections[].guides[]` | Lv2 내비용 |
| bound | `summary.bound` | FE 지도 표시용 |

## 미해결 / 후속
- guide `type` 코드(2·29 등) 정확한 의미표 → guidance 텍스트로 역매핑.
- traffic_state 코드 정확한 스케일 → 실응답 분포로 확정(0정보없음/1정체/3서행/4원활 관측됨).
- 카카오 **일일 쿼터** 수치 → 콘솔 확인 후 수집 규모 산정.
- 수집 대상 **O-D 목록 생성 방식**(지역 내 랜덤/POI 쌍) → 별도 설계.
